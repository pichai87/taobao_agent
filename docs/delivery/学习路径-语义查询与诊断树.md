## 先分清现在的两条入口

网页的“语义查询工作台”把你选择的指标、维度、日期交给 Java 编译成 SQL；它不调用模型。Agent 分析入口仍经过运行服务、工作流与工具调用，再把查出的两期数据交给确定性计算器。

两条入口都能使用本地语义编译器：工作台直接接收结构化表单，Agent 主链通过日查询工具间接编译。主链模型参数目前仍限制在 GMV/日期/品类，因此尚不等于模型可以选择全部指标和维度的动态 NL2MDL2SQL。

## 3. 语义计划怎样变成 SQL

阅读 [SemanticSqlCompiler.java](D:/dvelop/Javaweb/ecom-data-analysis-agent/ecom-agent-tools/src/main/java/com/ecom/tools/SemanticSqlCompiler.java) 的 `compile()`。

Semantic（语义）表示业务含义。例如用户选择 `GMV`，代码需要知道它对应哪项度量、如何汇总，而不是让用户记住数据库列名。

当前公式只有两类：

- `SUM`（求和）：例如 GMV 求和。
- `RATIO`（比率）：例如总订单数除以总 UV。

计算总转化率时，不能直接把不同品类的转化率相加。应先汇总订单数和 UV，再相除。

编译器先检查指标、维度、日期跨度和行数；随后生成固定语法结构，并把用户的日期与品类放在参数中。参数化查询的意思是：SQL 结构与用户数据分开，用户填写的内容不会直接变成 SQL 指令。

AST（抽象语法树）是解析器读懂 SQL 后得到的结构。这里用 JSqlParser 检查生成语句，再与可信编译结果比对。当前接口不接受用户随意传入 SQL，因此这是受支持子集的编译校验，不是任意 SQL 的万能安全判断器。

`ColumnLineage`（列依赖）记录这次编译结果用到了哪些已知源列。它不是读取任意 ETL 文件的字段血缘引擎。

练习：将指标换成 CVR，观察 SQL 中为什么出现除法和 `NULLIF`。`NULLIF(x, 0)` 在 x 为 0 时返回空值，避免除以零。

## 4. 数据库结果从哪里来

继续看 `JdbcSemanticWorkbench.query()`。它只执行本次可信编译器生成的 SQL，设置查询超时与最大返回行数，并记录审计。

查询会多取一条作为上限检查。如果超过用户限制，应报告结果超限；不能把截断后的一部分行悄悄当成完整总计。

当前数据依然是学习用合成数据。品类 UV 能相加依赖“品类访客互斥”的假设。真实访客可能同时浏览多个品类，未经去重就相加会算错。

练习：说明“SQL 执行成功”与“数据业务口径正确”为何是两项检查。

## 6. BigDecimal 与 Shapley 在这里解决什么

`BigDecimal` 是 Java 的十进制数类型，适合金额运算。`double` 是二进制浮点数，部分小数不能精确表示，因此金额不使用它来累加。

当前指标口径为：

```text
GMV = UV × CVR × AOV
CVR = 订单数 / UV
AOV = GMV / 订单数
```

这是一条可约分验证的恒等式。三个因素同时变化时，先替换 UV 还是先替换 CVR，会影响中间分配出的贡献。

Shapley（夏普利值）在这里的用法是：枚举三个因素所有六种替换顺序，把每个因素在各顺序中带来的金额差平均。它解决贡献分配的顺序偏差，不证明现实业务因果。

当前例子中 3000 元变成 2600 元：总 UV 不变、平均订单金额不变、订单转化率下降，因此转化率因素贡献 -400 元。再下钻到品类，家电的订单减少解释了这一差额。

阅读顺序：`diagnose()` 检查输入 → `factors()` 算三因素贡献 → `candidates()` 构造下层分支 → `expand()` 按预算递归 → `node()` 保存结果。

练习：用纸笔算出 6/1000 和 10/1000，说明这里的 CVR 为何叫“订单转化率”，而不能默认等同“支付买家转化率”。

## 7. 诊断树为何需要限制和剩余金额

[Diagnosis.java](D:/dvelop/Javaweb/ecom-data-analysis-agent/ecom-agent-domain/src/main/java/com/ecom/domain/Diagnosis.java) 中，`Node`（节点）保存当前值、对比值、贡献、子节点和停止原因。节点可以包含下一层节点，这就是递归结构。

当前选项包括：

- `maxDepth`：最多展开多少层。
- `maxNodes`：整棵树最多多少节点。
- `coverage`：按绝对贡献覆盖到多少比例。
- `minContribution`：小于多少元就不继续展开。

每个节点都满足：

```text
本节点贡献 = 已展示子节点贡献之和 + remainingContribution
```

`remainingContribution` 是尚未向下展开的金额；叶节点也会保留自己的金额。它不表示已经找到或未找到某个真实业务原因。

覆盖率使用“绝对贡献合计”。例如一个因素 +75 元、另一个 -75 元，净变化为 0，但不能因此说所有因素都没有变化。

缺失品类不能自行补成零；UV 或订单数为零时必须停止无法计算的分解；同一天不能解释成两期时间变化。当前只实现固定 GMV 公式和品类维度，更多公式与维度需要新的契约和测试。

## 8. 从 Java 结果到网页
