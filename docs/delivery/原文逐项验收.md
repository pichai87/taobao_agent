## 现有 28 项目录的逐项验收

本节以本轮开始时 `requirements/catalog.json` 和实际源码为基线。后续完成情况追加到本文末尾，避免将旧状态覆盖成虚假的历史完成记录。

### 01 `intent`：意图、日期、指标、维度

基线：部分。`IntentAgent` 只解析 goal/confidence，日期来自表单；不支持次意图。

验收：固定时钟下“昨天”“上周”“2026-09-12”得到确定日期；GMV、订单、UV、CVR、AOV 别名映射可核查；支持“解释 GMV 并比较两日”两个任务。低置信度有显式降级或澄清，认证失败不能伪装离线模型成功。字段格式正确与意图语义正确分别测试。

### 02 `supervisor`：专家分工与交接

基线：核心协作已实现。独立上下文、工具白名单、Query/Analysis 交接和预算有测试。Ops 只查看本人任务，未接 DataWorks。

验收：新增血缘、元数据、知识管理、诊断、分析任务能路由到有权限的专家；次意图的有序执行和证据传递可追踪。不能通过给工具起新名字制造“新专家”。外部运维只读范围及写操作审批必须明确。

### 03 `tool-loop`：专家工具调用循环

基线：已实现有限多轮 Tool Calling。用户已提交真实多 Agent 轨迹：意图 1 次、Query 2 次、Analysis 3 次，累计报告 4531 token。

验收：新工具在真实循环内被请求、执行、反馈，参数错误可有限修正；越权、超预算、空数据均不生成虚假成功报告。模拟决策集成测试与真实模型质量评测分开统计。

### 04 `harness`：执行约束与答案校验

基线：轮次、工具次数、交接次数、token、操作边界超时及取消均有约束；完整自然语言忠实度尚未验证。

验收：工具失败和错误日期不会漏到报告；工具输出中的指令不能扩大权限。模型最终文字涉及的金额、方向和引用可以核对；校验不了的解释明确为待核对。真实费用不能由缺失 token 或模拟 token 推算为零。

### 05 `semantic-mdl`：自然语言到语义模型再到 SQL

基线：未实现。`ApprovedSql` 只有两个固定模板。

验收：语义配置真实包含表、字段、指标、维度、必要筛选及允许关联；用户选择不同合法指标/维度能生成不同且正确的查询。不存在字段或未授权关系必须拒绝。若提供本地编译器，标注支持的 SQL 子集；WrenAI 实际适配另附服务版本、请求与结果证据。

### 06 `sql-generation`：生成、预演、有限修复

基线：未实现模型/语义驱动的候选 SQL。

验收：依据可用 Schema、已批准规则和片段构造候选查询；预演或检查失败时反馈结构化错误，限定修复次数。保存生成、拒绝、修复、最终执行四种证据，不能悄悄把失败候选换成无关固定模板。

### 07 `sql-gate`：SQL 执行闸门

基线：模板完全匹配、参数绑定和行数上限，尚无 AST 闸门。

验收：解析器判断单条只读查询，检查所有作用域中的表、列、函数、关联、日期条件及上限；覆盖 CTE、子查询、星号、别名绕过、多语句和危险函数。禁止 DDL/DML、写文件、存储过程和未声明表。数据库侧独立只读账号的拒写测试另行验收。

### 08 `knowledge-catalog`：L1 能力与表模型

基线：未实现。

验收：可查看/检索可回答问题、指标、表字段、维度、粒度和访问限制；批准版本与实际 Schema 相符；不允许模型使用未发布字段。接入新表后可检索而不改业务 Java 分支。

### 09 `knowledge-sql`：L2 SQL 片段

基线：只有代码内预置模板。

验收：实际执行成功的查询进入待审核区；审核前不召回、通过后可按表/指标复用；拒绝、重新编辑、停用有审计。检索片段不能绕过 SQL 闸门。

### 10 `knowledge-rules`：L3 业务规则

基线：四条种子规则；`JdbcKnowledge.recall` 返回全部规则，没有按场景检索。

验收：按指标/表/场景召回已发布且生效版本，报告提供来源与版本；冲突规则不能同时悄悄生效。验证新规则发布后真实影响查询和解释。

### 11 `knowledge-lineage`：L4 字段血缘

基线：未实现。

验收：从项目提供的 ETL SQL 解析字段来源、表达式及筛选；至少覆盖直接映射、聚合、JOIN、CTE、子查询、UNION、别名和可解析的 SELECT *。图谱命中与源码实时解析是不同事件；不支持方言时返回明确错误。正则抽取表名不能替代 AST 字段级血缘；本地依赖图不能冒称已部署 LightRAG。

### 12 `knowledge-metrics`：L5 指标注册

基线：数据库词典存在，公式与分解仍写死 Java。

验收：注册乘法、加法、比率公式；校验引用字段、单位、分母、维度和循环依赖；乘法恒等式须能还原目标指标。向导预览、人工确认、发布后，查询/诊断真正使用新定义。GMV 单个专用算法只能标为部分覆盖。

### 13 `knowledge-memory`：L6 会话记忆

基线：历史运行存在，无跨问题会话。

验收：“查 9 月 12 日 GMV”后问“那前一天呢”可复用同会话已确认指标；换用户/会话不可泄露。只保存受约束摘要，支持清除；记忆中的文字不能覆盖工具权限或冒充新的用户授权。

### 14 `knowledge-onboarding`：知识接入与发布

基线：未实现，Flyway 种子不是接入流水线。

验收：接入表结构、识别粒度和维度、从 ETL 提取候选规则、生成候选片段、人工审核发布；发布失败应保持旧版本可用。新 Schema 变化可使旧知识失效或重新审核。提供网页与可重复调用的脚本入口。

### 15 `recursive-attribution`：诊断树

基线：只计算两日品类 GMV 差额。

验收：合成数据上输出 GMV→UV/CVR/AOV→品类/指标的多层树；金额贡献守恒；每个节点有公式、当前/对比值、数据范围、贡献单位及停止理由。零分母、最大深度、贡献阈值、覆盖率、节点预算及环路均有边界测试。只有品类一个维度时不能标成全维度自动诊断；任何数值拆分均不等于业务因果证明。

### 16 `sandbox-analysis`：Python 分析沙箱

基线：未实现。

验收：运行时有实际进程/容器隔离，网络禁用、非特权、只读输入、独立临时输出、CPU/内存/时间/文件上限；超时能终止子进程。帕累托、透视等分析真实执行并返回受控图表；恶意文件/网络/子进程访问被阻止。没有隔离运行时则不执行模型代码，保留外部环境阻塞。

### 17 `data-routing`：数据源路由与回退

基线：仅本地 H2/MySQL 配置，无 ODPS/Hologres 实际连接。

验收：分析场景才选择加速源；不兼容 SQL、远程故障、表未挂载和缓存失效有明确处理与回退事件。未配置供应商时显示未接通，禁止给 H2 查询贴“via Hologres”标签。真实 ODPS/Hologres 账号、网络及数据为外部依赖。

### 18 `data-ingestion`：数据导入与质量

基线：90 天三品类合成数据。

验收：独立学习库导入有 schema、日期覆盖、重复、负值及孤立订单检查；区分退款、支付订单和访客口径。UV 只有品类互斥假设才可相加，真实去重 UV 不可沿用该假设。质量不合格应阻止诊断或明确缺数，不能只返回静默漏行的视图。

### 19 `evaluation`：Golden Case 多维评分

基线：JUnit 与六类固定协议对照，尚无完整真实模型评分集。

验收：固定问题、数据版本和期望结果；分别评分因素、树、工具、结论、SQL、证据；不适用维度是跳过而非 0 分。保存意图权重、模型配置、版本、耗时和供应商用量；能对比两版并输出失败项。规则评分、模型裁判和真实供应商运行必须分别标识，不能把脚本模型的 100% 当准确率。

### 20 `badcase`：失败案例闭环

基线：有错误码与事件，无独立管理和节点诊断。

验收：失败任务可关联问题、脱敏配置、数据版本、失败节点和证据；修复后运行同样例并展示前后差异。归因必须来自实际错误，所有节点通过但质量不足不能捏造为 SQL 故障。

### 21 `web-console`：用户可验收界面

基线：认证、任务、轨迹、报告和需求表已实现。

验收：所有新增的注册、知识审核、血缘、诊断树和评测有可用入口及空/失败状态；图表与表格同源；不得展示未执行的专家活动。保留新手释义和 SQL/证据可检查性。

### 22 `streaming`：浏览器真正接 SSE

基线：后端 `EventStreamController` 已有 SSE，网页 `pollRun` 仍轮询。

验收：网页消费服务器事件；凭事件序号断线续接、去重并保持顺序；终态最后批事件不漏；切换任务后旧连接释放；认证过期停止；慢客户端和连接上限有测试。只有后台 SSE 接口不算网页流式验收。

### 23 `browser-key`：临时模型配置

基线：内存 30 分钟、按账号隔离、地域白名单，已实现。

验收：新增专家、沙箱、导出、错误日志与评测均不泄露 Key；新功能不能绕过会话过期或清除。重启后失效明确告知。

### 24 `task-lifecycle`：运行状态

基线：持久化、幂等、确认、取消与离线检查点恢复已实现；模型模式不可续接。

验收：新增路径保留这些约束；取消后不继续查库/调用模型；恢复范围明确。用户本轮排除升级方案，因此不能擅自把升级方案中的完整模型持久恢复宣称为本轮现成功能。

### 25 `security`：账号和数据隔离

基线：Basic、CSRF、owner 隔离，属于本机范围。

验收：所有新 API、知识草稿、会话、图表文件、评测和下载均验证所有者与权限；真正组织/租户隔离需数据侧测试。本机演示账号不能视为企业 IAM。

验收：新增代码状态有对应测试依据；保留用户历史备注，不能在迁移中覆盖。外部依赖不因新增 adapter 或 skipped test 被勾为全部完成。

## 目录外需单独跟踪的原文和计划能力

- 表元数据、ETL 源码查看、字段血缘、SQL 开发：应有用户意图和 Query 工具路径，不能只提供后台 Java 类。
- 指标接入向导、SQL 待审区、规则管理、Schema 更新：属于独立管理闭环，需求勾选表不能代替。
- 诊断器的公式注册驱动、多路筛选和多维递归：一个固定 GMV Shapley 算法只是其中一部分。
- 运维专家的原文平台操作依赖具体供应商；本项目应先明确可执行的只读能力，写操作继续受原企业计划审批边界限制。
- 原企业计划的 Redis/Kafka/worker/RAG/监控组件仍须区分“规划、配置、实现、联调”；没有运行消费者不能算异步 worker 已完成。
- 原文图片中的 A/B 表类别策略、Harness 阈值、公式分类细节、诊断五步和评测权重尚待图片核实，不凭猜测补原文具体常数。

## 外部依赖与不可伪造的证据

- 淘宝内部 ETL、真实业务数据、TisPlus3：项目无授权资源，不能复制成“真实数据”。可提供本地功能替代并明确来源。
- DataWorks、ODPS、Hologres：需用户授权的服务、网络和最小权限账号；本地契约/模拟响应只证明适配逻辑。
- WrenAI、LightRAG：开源服务可单独部署，但必须记录实际运行版本和集成结果。本地语义配置/依赖图使用自己的名字。
- Python 隔离执行：需要可用隔离运行时。不能为消除依赖阻塞而在 Java 主进程旁不受限地执行模型代码。
- 真实模型回归：需要有效模型会话和有上限的费用预算；没有实跑即标“待真实模型验证”。

## 实施优先顺序

1. 语义模型、AST 闸门、知识查询与注册：先补数据与权限基础。
2. 指标公式、确定性诊断树、结构化意图：让新能力确实进入 Agent 链。
3. 知识审核、会话记忆、SSE 及网页入口：形成用户可操作闭环。
4. 固定样例与六维评测、失败案例：用实际证据检查功能。
5. 隔离沙箱、外部平台、生产依赖：实现可执行适配，实际环境不满足则保持阻塞状态，不降级成虚假完成。
