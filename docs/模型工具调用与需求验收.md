# 模型工具调用与需求验收

更新：2026-09-14。本次增加真实工具调用协议与网页验收表，但没有替你使用真实 Key 调用付费模型。

## 1. 先分清三种模式

- OFFLINE_RULES：规则识别问题，再执行固定六节点 StateGraph（状态图）。不调用模型，但确实查询数据库。
- 原有 LLM 分类模式：模型只选择意图，后续仍执行固定图。
- LLM_TOOL_CALLING：模型自己选择工具及参数，Java 校验并执行，将结果交给模型继续决策。网页配置后可以为新任务选择这种模式。

本篇最初交付的是有次数限制的单 Agent 循环，实现在 ToolCallingWorkflow.java。后续已新增实际多专家协作，单 Agent 保留作对照；当前架构和验证以 [多Agent协作与对照验证](多Agent协作与对照验证.md) 为准。
离线固定图仍使用 Spring AI Alibaba StateGraph；新循环是显式 Java 协议实现，不伪称整个循环由 Graph 框架驱动。

## 2. 网页怎么用

1. 启动项目，打开 [本机页面](http://127.0.0.1:8080/)，登录学习账号。
2. 在“模型配置”区域选择百炼地域，填写该地域 Key、模型名。默认模型名为 qwen-plus。
3. 若使用业务空间专属域名，填写业务空间 ID；旧的官方公共域名可留空 ID。
4. 阅读并勾选数据发送与计费提示，点击“保存临时配置”。这一步只保存配置，不验证外部连通性，也不扣模型费用。
5. 确认执行方式为“模型自主选择工具”，保留默认日期和问题；初次建议勾选“提交后，确认才执行”。
6. 确认后看轨迹中的“大模型决策”“工具调用”“受控查询”和最终报告。只有生成成功报告，才完成该次分析。
7. 用完点“清除密钥”或退出。不要把 Key 发到聊天、写进问题或写进验收备注。

允许的官方地址：

- 北京：`https://dashscope.aliyuncs.com/compatible-mode/v1/chat/completions`。
- 新加坡：`https://dashscope-intl.aliyuncs.com/compatible-mode/v1/chat/completions`。
- 业务空间：北京 `{id}.cn-beijing.maas.aliyuncs.com`；新加坡 `{id}.ap-southeast-1.maas.aliyuncs.com`，路径相同。

Key 必须与地域和模型权限匹配。只接受白名单地域和 qwen 系列名称；不接受任意自定义 URL，也不跟随 HTTP 重定向。
模型需支持函数调用。保存成功只表示本地格式检查通过，不表示百炼认可了 Key 或模型名。
协议参考：[百炼兼容接口](https://help.aliyun.com/zh/model-studio/compatibility-of-openai-with-dashscope)、[官方函数调用说明](https://www.alibabacloud.com/help/en/model-studio/qwen-function-calling)。

## 3. 什么叫模型决定工具调用

Tool Calling（工具调用）：模型返回工具名和参数，由应用执行函数；模型没有数据库密码，也不能自己越权运行 SQL。

比如默认问题可能经历以下过程，但顺序由模型决定，并非固定脚本：

1. explain_metric：读取 GMV 口径与证据。
2. query_daily：参数 period=current / previous，分别查询表单指定的日期。
3. compare_gmv：用 Java BigDecimal 计算差额及品类贡献。
4. 模型收到计算结果，再给出中文解释。

其他工具：query_trend（七日查询）、summarize_gmv（汇总）、rank_categories（品类排序）。
当前只开放这六种工具，不包含生成任意 SQL、删改数据、执行 Python 或读文件。

报告里的金额由 Java 计算，模型解释单独展示并提示核对。默认合成数据应为 2600 / 3000 元，差额 -400 元。
“家电贡献 -400 元”不能直接推出“促销失效”之类业务因果。
仅查询口径不能让数字问题通过；明显的对比问题还要求两期计算结果。纯定义豁免只允许有限的明确问法，如“GMV 是什么”。
这些规则不等于完整语义理解或幻觉评测；模糊问法、复杂多意图仍可能失败。

## 4. 密钥和调用限制

- 浏览器 Key 输入框保存成功后清空；不写 URL、浏览器本地存储或任务 JSON。
- 后端 Key 保留在单实例内存，30 分钟后不可使用；清理线程定期擦除 char[]。清除、退出或重启后需要重新配置。
- HTTP 请求与 Java String 可能有临时副本，不能承诺操作系统/堆内存完全不存在明文；不要开启请求体、HTTP wire 或堆转储调试。
- 持久化任务仅保存不可推导 Key 的会话 ID。配置查询只返回模型、地域、地址和过期时间；不同账号不能使用别人的 ID。
- 非本机连接要求 HTTPS；当前仍只监听 127.0.0.1。此功能不是生产密钥管理服务。
- 每次任务最多 8 轮模型请求、12 次工具请求，每轮最多 4 个工具；单账号同时仅执行一个模型任务。
- 单次网络请求最多 25 秒；任务在操作边界检查 90 秒预算。停止并不保证供应商取消计费。
- 单次发送上下文最多 100 KB、接收最多 256 KB；设置 max_tokens=1024，并在模型报告的累计 token 超过 20000 后停止。
- token（模型文本计量单位）限制不是金额上限；供应商缺失 usage 时无法精确计数。需要在百炼侧设置额度与预算告警。
- 不自动重试网络失败，也不会失败后偷偷降级成离线结果。最多两次参数/前置步骤纠错会额外消耗模型轮次。
- 取消或清除 Key 阻止后续工具/模型步骤；已发送的请求无法撤回，正在执行的只读查询只能等待查询超时或返回。
- 模型任务不保存完整消息历史，进程中断后不能从旧对话续跑。网页不提供该模式的“恢复”按钮，请重新配置后新建任务。

错误例子：MODEL_AUTH_FAILED 为供应商认证失败；MODEL_RATE_LIMITED 为限流/额度问题；MODEL_EVIDENCE_REQUIRED 为缺少数据证据；TOOL_NOT_ALLOWED 为请求了未授权工具。

## 5. 需求实现与验收表

登录后展开“需求实现与验收表（按原文架构）”，会加载 28 个核心验收项。

- 已实现：仅表示这一行写明的代码范围已完成，不表示整个原文系统完成。
- 代码完成度：尚未实现 / 部分实现 / 本项已实现，与勾选同步。
- 验证程度：尚未验收 / 自动化测试 / 本机网页端到端 / 真实模型端到端。
- 需要打回更新：独立的返工标记，可以对已经实现但验收发现问题的功能打回。
- 验收备注：写验证方法、观察结果、仍缺什么。必填，最多 3000 字；不要粘贴密钥。
- 保存此项：逐行保存；刷新、退出前先保存。刷新表格会在有未保存修改时询问是否放弃。

推荐备注：`默认日期查询得到 2600 / 3000；工具序列可见。未测试真实百炼请求，暂不能通过真实模型验收。`
若出现版本冲突，先复制自己修改的备注，刷新并结合最新记录重新保存，不覆盖别人刚保存的内容。

目录在 `ecom-agent-bootstrap/src/main/resources/requirements/catalog.json`，随代码提交仓库。
个人勾选与备注在数据库 `requirement_review`，修改历史在 `requirement_review_audit`；由版本号检查并发修改，按登录账号隔离。
Git 提交不包含本地数据库，所以不会把个人运行记录或验收备注上传到 GitHub。更换机器需另行迁移/备份数据库。
目录更新不会覆盖已有个人记录；需要重新验收并主动更新旧记录。当前没有审计历史查询页面，也没有正式多人审批流程。

## 7. 学习顺序

1. 前端 form → app.js 的 model-form 提交：看表单如何变成 JSON。
2. ModelSessionController → MemoryModelSessions：看接口、对象引用、Map 和生命周期。
3. RunService：看请求如何选择离线图或模型循环。
4. ToolCallingWorkflow：看 while/for 的循环思想、工具白名单、前置条件与退出条件。
5. BailianToolGateway：看请求中的 tools、响应中的 tool_calls，以及用 tool_call_id 关联结果。
6. RequirementController → RequirementService → JdbcRequirementStore：看分层、持久化和乐观锁（版本不一致就拒绝覆盖）。

练习：先不看全部框架，只解释“模型要求查数据”与“Java 真正查数据”为什么是两步，再给一条需求填写有证据的验收备注。

自动化测试使用模拟供应商决策和真实测试库；实际网页验证、通过数量和未覆盖项请看 [验证记录](验证记录.md)。
