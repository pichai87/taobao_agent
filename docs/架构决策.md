# 架构决策 ADR

ADR = Architecture Decision Record，架构决策记录。

## ADR-001：保留企业模块边界，采用模块化单体

API 依赖 application；application 依赖 agent-core；agent-core 使用 domain 的端口。
infrastructure 实现数据库、模型等端口；bootstrap 统一装配。
tools 和 knowledge 负责可独立测试的算法、规则。

不为了目录数量建立网络微服务。mcp-server、worker、web 已预留，
但没有实现的模块明确写出状态，不能将空目录计为完成能力。

## ADR-002：使用真实 StateGraph，但不冒称自主多智能体

固定六节点图由 Alibaba Graph 1.1.2.2 调度。意图决定查询/趋势/解释分支，
数值由 Java 计算，校验失败不生成报告。
目前图节点在一次运行中创建，便于隔离闭包状态；高吞吐前再优化为可复用定义。

模型仅分类，不生成任意执行计划、SQL、Python。动态计划校验、Supervisor、
工具循环、重试路由、结构化模型报告还未完成，属于原路线的后续实现。

## ADR-003：SQL 精确白名单先于自由 Text-to-SQL

执行入口只接受 ApprovedSql 中的两个模板，日期参数单独绑定。
所有模型输出都没有路径变成 SQL 结构。
这是已审核分析技能的实现，不是通用自然语言转 SQL 引擎。

将来放开 SQL 生成，必须新增 AST（抽象语法树）审核、表/列/函数权限、
查询成本控制、注入评测，以及数据库只读账号测试。不能删掉白名单就直接放行。

## ADR-004：数据库检查点、单实例运行

每完成节点保存 Snapshot.completed 和中间数据。
启动时将残留 RUNNING/QUEUED 标为 INTERRUPTED，由所有者调用 resume。
恢复时跳过已经完成的节点。节点动作与检查点并非同一事务；
崩溃窗口可能重复执行只读查询与产生重复审计，不承诺 exactly-once。

当前只能运行一个应用实例。多实例前需要任务租约、心跳、fencing token
（防止过期执行者继续写入的编号），不能直接在 Kubernetes 中扩容。
计划中的 Redis/Kafka 方案仍需要完成，不把本地线程池称为分布式调度。

## ADR-005：明确指标语义和证据边界

GMV 是已支付订单金额，是否扣退款由明确口径决定。
品类贡献求和必须等于总 GMV 差额；贡献不是因果。
趋势显示七天明细，摘要只统计目标日，不能把七日 UV 加总叫作去重人数。
定义查询不输出伪造的数值数据。

## ADR-006：参考与版本

当前锁定 Java 21 字节码、Boot 3.5.8、Spring AI 1.1.2、Alibaba Graph 1.1.2.2。
该组合依据 [Alibaba 对应版本源码](https://github.com/alibaba/spring-ai-alibaba/tree/v1.1.2.2)，
不是声称这些都是最新版本。公开部署前须做依赖漏洞扫描与补丁升级回归。

模型适配采用 Spring AI 的 OpenAI 兼容客户端。
OpenAI Docs 核对的是 [Chat Completions 接口](https://developers.openai.com/api/reference/resources/chat/subresources/completions/methods/create)；
不同兼容供应商的字段支持仍需真实联调。没有购买或调用付费模型。
本地模型适配测试使用 mock（模拟响应），不是模型准确率评测。
