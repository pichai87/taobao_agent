# 运行与部署

## 本机配置

默认 local：H2 文件保存在启动工作目录的 var/agent.mv.db。
scripts/start.ps1 固定从仓库根目录启动，避免相同项目产生多份不易察觉的数据库。
停止服务用 Ctrl+C。不要直接删除数据库排障；先停止进程并备份 var 目录。

同一数据库不允许启动两个应用实例。另开测试实例应使用不同数据库。
学习密码仅用于回环地址，本机脚本也拒绝把它发送到外部站点。

## 模型配置（尚未真实联调）

设置 AGENT_MODEL_MODE=llm、MODEL_API_KEY、MODEL_BASE_URL、MODEL_NAME。
使用支持 Chat Completions 的 HTTPS 服务；BASE_URL 是客户端基础地址，
默认请求路径由 Spring AI 客户端补 /v1/chat/completions，供应商不同须核对完整 URL。

密钥仅放运行时环境变量，不放 Git、不贴入聊天。
模型名由供应商账号真实可用清单决定；不会擅自替换成当前聊天中的 Codex 模型。
应用模型接口与 Codex 账号额度是两件事。

只把用户问题送给模型分类，不把订单明细送出。问题本身也可能包含敏感信息，
连接第三方前须确定数据处理政策。一次规划请求，连接超时 5 秒、读取超时 25 秒，
不自动重试。60 秒任务预算是节点边界检查，不是可强杀整个进程的硬时限。

## MySQL 本机联调模板

当前没有 Docker，因此以下为待验证部署路径，不是已经运行的服务。

1. 将 .env.example 复制为 .env，设置独立高强度密码。
   reader 密码需 16–128 位英文字母、数字、下划线或横线，以匹配初始化脚本。
2. 在仓库根目录执行：
   `docker compose --env-file .env -f deploy/compose.yml up -d mysql`
3. 给应用进程设置 SPRING_PROFILES_ACTIVE=mysql、
   MYSQL_APP_PASSWORD、MYSQL_READER_PASSWORD、APP_PASSWORD。
   .env 不会自动加载进 PowerShell/Java 进程；需自行设置进程环境变量。
4. 启动应用，Flyway 建表。初始化脚本已建立 reader 账号，但尚未授予视图权限。
5. 管理员登录 MySQL，执行 deploy/mysql/grant-reader.sql。
6. 独立学习库需要示例数据时，执行 infrastructure 中 db/local/V2__synthetic_seed.sql。
7. 使用 reader 账号验证 SELECT analytics_daily 成功，
   SELECT biz_order、SELECT agent_run、DELETE、UPDATE 均失败。

MySQL 应用账号当前兼任迁移账号，权限较大；正式部署必须拆成 migration 和 app 两账号，
Flyway 由发布流程独立执行，业务运行账号仅有任务相关表的必要读写权限。
setReadOnly(true) 不能代替 GRANT 权限控制。

容器文件只绑定本机端口。Redis 在 optional-redis profile 中，当前应用未使用它。
不要为了“全栈”启动未接入的服务。

## 镜像与 CI

`docker build -f deploy/Dockerfile -t ecom-agent:local .`
生成非 root 用户的 JVM 镜像。镜像构建跳过测试，前一步须执行 mvn verify。
公开部署需显式 mysql 配置和 HTTPS 网关，不要直接用默认 local 镜像暴露公网。

GitHub Actions 配置运行 JDK 21 编译、测试、打包；本机仅创建配置，
没有上传代码、创建远程仓库或触发远程 CI。
Docker 基础镜像与依赖上线前须锁定 digest、漏洞扫描和供应链检查。
