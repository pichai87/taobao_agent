# 网页验证与学习指南

更新：2026-09-14。目标：不用读终端 JSON，也能判断一次分析是否成功。

## 1. 打开与登录

打开 [本机控制台](http://127.0.0.1:8080/)。默认学习账号 `analyst`，密码 `local-learning-only`。
点击“连接服务”。这些是本机示例凭据，不能用于公网部署。

若旧标签仍显示 ERR_INVALID_AUTH_CREDENTIALS，先新建标签打开同一个网址。
旧版本没有登录页，新版公开登录页，但业务接口仍然需要账号密码。
不要通过关闭认证、防火墙或 CSRF 来解决问题。

页面只把凭据保存在当前页面内存中，不写 localStorage 或日志。
退出/刷新会清除页面里的凭据与报告，不会取消已经提交的任务；重新登录后可从“最近任务”找回。

## 2. 跑一次默认示例

保持以下输入：

- 问题：GMV 为什么下降。
- 目标日期：2026-09-12；对比日期：2026-09-11。
- 不勾选“提交后，确认才执行”。

点击“开始分析”，完成后应看到：

- 目标日 GMV：¥2,600；对比日：¥3,000。
- 差额：-¥400；变化率：-13.33%。
- 家电贡献：-¥400；美妆、食品均为 ¥0。

GMV（Gross Merchandise Volume，商品交易总额）：本项目统计已支付订单金额，当前口径不扣退款。
数据是本项目的合成教学数据，不是真实淘宝经营数据。

## 3. 怎样判断三部分正常

“后端服务”显示接口可访问、健康检查通过：说明登录时服务已响应。不是持续监控。

“业务数据库”显示本次业务查询已完成：说明本次查询步骤通过；金额和明细来自真实 H2 查询。
这不能证明所有数据库功能、MySQL 权限或生产数据都正确。

“Agent 工作流”显示本次完成：说明此次任务成功生成报告。
展开执行轨迹，可依次看到：识别问题 → 读取口径 → 查询 → 计算 → 校验 → 报告。

Agent（智能体）：按步骤调用工具完成任务的程序。
当前 OFFLINE_RULES（离线规则模式）用关键词选择意图，不调用大模型，不需要模型 API Key（接口密钥）。
StateGraph（状态图）是真实执行的。上述六步描述离线模式；现在另有单 Agent 工具循环和多 Agent 专家协作，均有预算与权限约束，不是无限自由执行。

## 4. 再试三个场景

1. 勾选“提交后，确认才执行”：任务先等待，不查询业务表；点“确认并执行”才运行，也可取消。
2. 问“GMV 是什么”：应显示定义，不应虚构金额；数据库提示“本次仅解释定义，不查询业务表”。
3. 问“GMV”，目标日期改成 2000-01-01：应失败并显示 NO_DATA（没有数据），不出现假的成功报告。

还可以问“GMV 七天趋势”，看 7 天 × 3 品类的 21 条明细；问“GMV 排名”看三个品类排序。
日期始终以输入框为准，不会自动理解并替换你在问题中写的日期。

## 5. 常见状态与下一步

- 等待你确认：点确认或取消；不是服务卡住。
- 执行中：页面每次请求结束后约 800ms 再读取一次。这叫轮询，不是大模型思考动画。
- 分析失败：看页面中的中文原因及错误码，修改输入后重新提交。
- 执行中断：可尝试“从检查点恢复”；只支持中断任务，不支持恢复失败/已取消任务。
- 连接中断：不代表后台任务被取消。先检查服务是否运行，恢复连接后重试进度或查历史任务。

SQL（结构化查询语言）：数据库查询语句。展开报告末尾可看审核过的模板和指标口径。
“品类贡献”只说明金额变化来自哪些品类，不足以断言促销、竞争或用户行为是原因。

## 6. 服务停止后怎样启动

电脑重启后需要重新启动后端，在 PowerShell 执行：

```powershell
cd D:\dvelop\Javaweb\ecom-data-analysis-agent
.\scripts\start.ps1
```

启动窗口保持打开。修改源码后，先停止该项目旧进程，再执行 build.ps1 和 start.ps1。
Windows 上运行中的 JAR 可能被锁定；不要删除数据库来解决打包问题。
若提示 8080 已占用，先确认已有项目是否已经能访问，不要重复启动或随意结束别的进程。

## 7. 后续看代码的顺序

1. index.html：form 表单和每个结果区域。
2. app.css：布局、间距、颜色；`[hidden]` 控制隐藏区域。
3. app.js：表单提交 → fetch 发送请求 → pollRun 获取进度 → renderReport 显示结果。
4. RunController.java：接收请求，调用应用服务。
5. RunService.java / AnalysisWorkflow.java：任务状态与六步执行。
6. JdbcAnalyticsReader.java：受控 SQL 查询；AttributionCalculator.java：金额计算。

页面文件在 `ecom-agent-bootstrap/src/main/resources/static/`，不需要另装 Vue 或启动第二个服务。
原计划的 Vue/ECharts、MCP、向量检索和多租户等仍按实施状态继续建设，并未宣称全部完成。

## 8. 新增：网页 Key 与需求验收

现在可在网页保存 30 分钟有效的百炼临时配置，再选择“多 Agent 专家协作”或“单 Agent 工具调用（对照模式）”。保存不等于外部模型验证通过，重启需重新填写 Key。
登录后展开“需求实现与验收表”，逐行修改勾选、验证级别、返工和备注并保存；重启仍保留已保存记录。
操作步骤与原文差距见 [模型工具调用与需求验收](模型工具调用与需求验收.md)。不要将 Key 填入聊天、问题或验收备注。

多 Agent 任务会增加“协作链”：仅展示实际参与角色、模型请求次数和专家交接。Supervisor 是规则调度，不计为额外模型请求；历史单 Agent 任务不会改成多 Agent。金额正确、证据完整、协作完成才可验收，不以角色数量代替质量。学习与对照步骤见 [多Agent协作与对照验证](多Agent协作与对照验证.md)。
