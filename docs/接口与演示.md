# 接口与演示

基址 http://127.0.0.1:8080。根路径现在提供公开的登录页面，业务接口仍需认证。
仅 `/`、`/index.html`、`/app.js`、`/app.css` 及健康检查公开；没有放开全部接口。
网页操作见 [网页验证与学习指南](网页验证与学习指南.md)。

内置页面采用串行 HTTP 轮询读取任务及增量事件，不使用 SSE。
等待确认、完成、失败、取消、中断时停止轮询；确认/恢复后重新开始。
网络失败时保留任务编号并提供重试，不无限请求，也不把未知状态当成成功。

## 认证及请求顺序

HTTP Basic：通过 Authorization 发送账号密码，真实网络必须使用 HTTPS。
CSRF：防止浏览器被第三方页面诱导执行写操作的令牌。

1. 带认证 GET /api/csrf，保留返回 token 和会话 Cookie。
2. 每个 POST 带相同认证、Cookie 和返回的令牌头。
3. 提交任务时另带 Idempotency-Key，推荐 UUID。

scripts/smoke.ps1 已实现以上流程。
网页也执行同样流程；认证失败通过表单显示，不依赖浏览器的 Basic 弹窗。
凭据保存在页面内存中，不写 localStorage；退出/刷新清除页面状态，不取消后台任务。

## 提交与结果

POST /api/runs：

```json
{
  "question": "GMV 为什么下降",
  "date": "2026-09-12",
  "compareDate": "2026-09-11",
  "metric": "GMV",
  "reviewRequired": false
}
```

响应包含 id、status、mode。任务异步运行，通过 GET /api/runs/{id} 读取。
完成后 report 含 conclusion、data、evidence、sql、limitation。
数据中的 changeRate=-0.133333 是比例，显示百分数时乘 100。

question 最多 2000 字符。date 必填。compareDate 省略时为目标日前一天。
相同用户、相同幂等键、相同规范化请求返回相同任务；
同键不同请求返回 409。任务属于认证用户，不接受 owner 请求字段。

## 其余接口

- GET /api/capabilities：真实模式和能力边界。
- GET /api/metrics：指标口径字典。
- GET /api/runs：自己的最近 50 个任务。
- GET /api/runs/{id}/events?after=0：按序号读取最多 1000 条事件。
- GET /api/runs/{id}/stream：SSE（服务器推送事件），支持 Last-Event-ID 或 after 重放。
- POST /api/runs/{id}/approve：确认待审核任务。当前是所有者确认，不是双人复核制度。
- POST /api/runs/{id}/cancel：取消未完成任务，节点边界生效。
- POST /api/runs/{id}/resume：仅恢复 INTERRUPTED；不能恢复 FAILED/CANCELLED。
- GET /actuator/health：存活/依赖健康信息；默认不暴露详情。

SSE 连接最多 32 个，共用 2 个调度线程，每 500ms 推送，最长 65 秒。
最终状态或待确认状态结束连接。中断重连需带事件序号，客户端自己做去重。

## 错误含义

INVALID_REQUEST：字段或 JSON 不合法。
RUN_NOT_FOUND：任务不存在或不属于当前用户；不泄露他人任务存在性。
IDEMPOTENCY_CONFLICT：重复键携带了不同请求。
INVALID_RUN_STATE：当前状态不能执行该动作。
METRIC_NOT_SUPPORTED：当前只支持 GMV 分析。
NO_DATA / NO_COMPARISON_DATA：目标日/对比日没有数据。
CAPACITY_EXCEEDED：线程池已满，请稍后用新键提交。
MODEL_PLAN_REJECTED：模型返回内容不是许可的意图。
MODEL_MODE_CHANGED：恢复时运行模式与原任务不一致。
EXECUTION_FAILED：未预期执行失败；通过服务端日志中的 runId 排查。

查询阶段错误记录在任务 status/errorCode 中，不意味着提交 HTTP 请求本身失败。

## 网页模型配置与验收表接口（2026-09-14）

所有下列接口需要认证，POST 同时需要 CSRF；Key 只通过本机 HTTP 或远程 HTTPS 传输。

- POST /api/model-session：字段 provider、workspaceId、model、apiKey、consent；返回 id、模型、官方 endpoint、expiresAt，不返回 Key。不调用外部模型。
- GET /api/model-session：返回当前浏览器会话 configured 和不含密钥的 session 元数据。
- POST /api/model-session/clear：清除本浏览器会话的临时 Key。
- POST /api/runs：可额外传 modelSessionId 与 executionMode（LLM_MULTI_AGENT / LLM_TOOL_CALLING）。有会话引用但省略 executionMode 时兼容旧单 Agent；没有会话引用时沿用服务器默认模式。显式模型模式必须有会话引用。禁止把 apiKey 写入分析请求。
- GET /api/requirements：目录版本、原文链接及当前用户的 28 项需求。
- POST /api/requirements/{id}：保存 implemented、extent、verification、rework、notes、version。返回新版本。

extent 为 NONE / PARTIAL / IMPLEMENTED；implemented 仅当 extent=IMPLEMENTED 时为 true。
verification 为 NOT_TESTED / AUTOMATED / LOCAL_E2E / LIVE_PROVIDER；只是验收记录，不由勾选自动证明。
notes 必填且最多 3000 字，version 初次为 0；过期版本返回 409 REVIEW_VERSION_CONFLICT，不能静默覆盖。
模型模式任务不允许 resume，返回 MODEL_RUN_NOT_RESUMABLE；清除配置后的待确认任务无法批准，需要重新建任务。
完整操作与模型费用边界见 [模型工具调用与需求验收](模型工具调用与需求验收.md)。

多 Agent 的接口兼容、角色、共享预算与对照实验见 [多Agent协作与对照验证](多Agent协作与对照验证.md)。GET /api/capabilities 的 multiAgent 返回模式、预算和专家清单；清单是能力声明，不表示某次任务全部调用了这些专家。
